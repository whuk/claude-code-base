# /rw:reflect — 작업 회고와 지침 반영

긴 작업을 마친 뒤 현재 대화에서 **다음 작업에서도 다시 일어날 수 있는** 교훈을 뽑고, 그 교훈을 기존 지침 파일의 수정안으로 만듭니다. 교훈을 기억에만 두면 다음 세션의 에이전트는 같은 실수를 반복하므로, 파일에 반영해야 회고가 효과를 냅니다.

대상은 이번 작업의 결과물이 아니라 **작업 방식을 정하는 지침**(`.claude/` 아래 문서)입니다. 결과물의 결함 수정은 이 커맨드의 범위가 아닙니다.

## 1단계: 회고 대상 확인

1. 회고 근거는 현재 대화와, 이번 작업에서 만든 커밋·PR 코멘트입니다. 커밋은 `git log`로, PR 코멘트는 `gh pr view {번호} --comments`로 확인합니다.
   ```bash
   git log --format='%h %s%n%b' {작업 시작 커밋}..HEAD
   ```
2. 대화가 요약으로 압축된 구간은 원문이 아니라 요약에 근거합니다. 그런 구간이 있으면 결과 보고에 명시합니다.
3. `$ARGUMENTS`에 회고 초점이 있으면 그 주제와 관련된 구간만 봅니다.
4. 대화가 짧거나 사소하거나, 에이전트가 기존 지침을 그대로 따라 문제없이 끝났으면 교훈이 없다고 보고하고 **중단**하세요. 교훈을 억지로 만들지 않습니다.

## 2단계: 교훈 후보 추출

아래 세 관점으로 대화를 훑어 후보를 모읍니다. 후보마다 **무슨 일이 있었는지**(증거: 대화 속 지점, 커밋 SHA, PR 코멘트 링크)와 **교훈 한 문장**을 적습니다.

- **판단**: 사용자가 정정한 지점, 되돌리거나 다시 한 작업, 리뷰에서 지적받은 결함, 질문했어야 했는데 추측한 지점.
- **도구**: 같은 수작업을 반복한 곳, 실패한 명령과 그 원인, 지침에 없는 우회 방법을 쓴 곳.
- **발산**: 처음부터 다른 방법을 택했다면 더 빨리 끝났을 지점. 실제로 택한 경로와 비교해 적습니다.

## 3단계: 걸러내기

후보마다 다음을 판정하고, 하나라도 해당하면 기각하고 이유를 남깁니다.

1. **재발 가능성 없음**: 이번 작업에만 있던 우연한 사정이어서 다음 작업에서 다시 일어날 수 없다.
2. **이미 지침에 있음**: 기존 지침이 이미 다루고, 그대로 따랐다면 막혔을 일이다. 이때는 지침을 수정하지 않습니다. 다만 지침이 있는데도 따르지 않은 이유가 지침의 위치나 표현 문제라면, 그 문제를 새 후보로 다시 올립니다.
3. **기존 규칙과 충돌**: 반영하면 `CLAUDE.md`나 다른 지침과 모순된다. 충돌을 해소하는 방안이 있으면 그 방안을 후보로 다시 올립니다.

## 4단계: 반영 위치 분류

남은 교훈을 반영 방식에 따라 나눕니다.

### 경로 A: 구조로 강제할 수 있는 교훈

린터, 테스트, 스크립트, 타입으로 막을 수 있으면 문서 수정안을 만들지 않고 **`/rw:correct` 후보**로 분류합니다(`STYLE_GUIDE.md` 9번). 실제 적용은 사용자가 `/rw:correct {교훈}`으로 실행합니다.

### 경로 B: 판단이 필요한 교훈

수정할 파일과 절을 정하고 수정 전·후 문안을 씁니다.

- 새 파일보다 **기존 파일의 해당 절**을 고치는 쪽을 우선합니다.
- 교훈이 한 커맨드나 에이전트에만 해당하면 그 파일에 씁니다. 여러 파일에 걸치면 rules나 guides에 씁니다.
- `CLAUDE.md`는 매 세션 로드되므로 모든 작업에 해당하는 교훈일 때만 씁니다.
- 실패 사례 예시를 함께 둡니다.

## 5단계: 사용자 확인

채택한 교훈마다 증거, 분류(경로 A 또는 B), 경로 B의 수정 전·후 문안을 보여주고 **적용 여부를 확인받습니다.** 사용자가 일부만 승인하면 승인된 수정안만 6단계로 넘깁니다. 모두 거절하면 결과 보고로 넘어갑니다.

## 6단계: 수정안 적용

1. `.claude/guides/STYLE_GUIDE.md`를 먼저 읽고 수정할 문서의 유형 규약을 따릅니다.
2. 승인된 수정안을 적용합니다.
3. 수정한 절의 번호가 바뀌었으면 그 번호를 인용하는 다른 파일을 찾아 함께 고칩니다.
   ```bash
   grep -rn '{파일명}' .claude README.md
   ```

## 결과 보고

- 채택한 교훈: 증거, 분류, 적용한 파일과 절.
- `/rw:correct` 후보: 교훈과, 그대로 붙여 실행할 수 있는 `/rw:correct {교훈}` 문장.
- 기각한 후보와 3단계의 기각 이유.
- 요약으로 압축된 구간에 근거한 교훈이 있으면 그 사실.

## 하지 말아야 할 것

- 사소한 대화에서 형식을 채우려고 교훈을 만들지 않는다.
- 증거(대화 속 지점, 커밋, PR 코멘트) 없는 교훈을 채택하지 않는다.
- 구조로 강제할 수 있는 교훈을 문서 수정만으로 반영하지 않는다(4단계 경로 A).
- 다른 파일로 충분한 교훈을 `CLAUDE.md`에 쓰지 않는다.
- 사용자 확인(5단계) 없이 수정안을 적용하지 않는다.
- 이번 작업의 결과물(코드, 문서 산출물)을 이 커맨드로 수정하지 않는다.
- 자동 커밋하지 않는다.
